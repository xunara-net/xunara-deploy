## Why

同步正式运行版本与已验证的代码清理成果，避免线上长期保留旧构建。
只更新服务端二进制和两个前端静态产物，不借部署混入新功能、套餐调整或配置重写。

## Compatibility impact

- 使用干净提交重新构建：Server 为 Go 1.27.1 / Linux AMD64 / CGO 关闭，二进制
  记录完整 VCS revision 且 `vcs.modified=false`；两个前端按锁文件安装并构建。
- 发布前确认只有一个控制面实例；短暂维护阻断代理侧控制面请求，停止服务后
  保存完整状态、环境 / 密钥配置、旧二进制与两个前端，再切换新版本。
- 恢复公网前，所有数据库文件集合、schema、版本及账户 / 凭据 / 节点 / 地址 /
  网络配置保护字段与冻结快照一致；会话核对排除活动时间及将在五分钟内自然到期的记录。
- 不更换现有正式证书，不改 nginx 最终配置或文件 UID / GID / 权限；不移动设备、
  重置现有密码 / 令牌、重编号地址或修改套餐；官方协议与已发布迁移未变。
- 新静态资源先发布、入口文件最后原子切换；旧哈希资源保留给已打开的浏览器，
  不是在源码中继续维护两套实现。旧公开 Python 检查地址仍明确返回 410。

## Security impact

凭据只用于受保护的 SSH 输入、进程环境 / 请求头或正文，未进入 URL、参数、
公开报告或 Git。数据库、配置和证书备份只保存在服务器 root 私有回滚目录。
正式站及原生客户端均使用系统信任链验证 TLS，没有使用跳过 HTTPS 验证的方式。

线上验证仅创建两个随机命名的自有临时网络，在其中完成普通登录、隔离与设备
审批；随后只删除这两个活动测试网络。保留正常审计 / 归档，不修改其他用户或设备。
后台认证页只做匿名可用性验证，不绑定、解绑或重置现有管理员凭据。

- 线上 `/health` 返回 `pass`、`/version` 为 `dd158e9`；两个前端入口及清单内

- 320 / 390 / 768 / 1440px 四档浏览器下，用户及管理员登录页可访问且无水平

  字段与维护快照核对通过。

## 回退边界

已创建本次发布前的 root 私有一致性快照，包含旧二进制、前端、完整状态与配置。
本次无迁移，可在重新维护、停止控制面后回退已确认兼容的产物；恢复写入后不能
覆盖旧数据库快照。发布过程未执行数据库恢复，未以旧 WAL 混用新状态。

私有运行日志、快照与校验清单不进入公开文档或仓库；需要排障时在服务器授权范围
内查阅。不要把临时网络通过验证扩展为原有第三方应用、全平台客户端或实时数据面
均已验收的结论。
